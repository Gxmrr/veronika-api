# VERONIKA — Booking API

Собственный учебный API для записи на маникюр (Node.js, Express, PostgreSQL). Не связан с Queue.

## Маршруты

- `GET /api/health` — проверка сервера и базы
- `GET /api/slots?date=2026-11-16&service=color` — подсказки свободных часов с шагом 15 минут
- `GET /api/availability?date=2026-11-16&service=color&time=13:07` — проверить любое выбранное время (до минуты)
- `POST /api/bookings` — создание записи (JSON: имя, телефон, услуга, дата, время)
- `GET /api/bookings` — приватный список записей, требует `Authorization: Bearer ADMIN_TOKEN`
- `PATCH /api/bookings/:id` — перенос существующей записи на дату/время (только администратор, JSON `date` и `time`)
- `DELETE /api/bookings/:id` — удаление записи (только администратор, с подтверждением в интерфейсе)
- `GET /admin` — панель мастера для просмотра записей и управления перерывами по секретному ключу
- `GET /api/breaks` — закрытые окна (нужен `Authorization: Bearer ADMIN_TOKEN`)
- `POST /api/breaks` — закрыть свободный промежуток; JSON `date`, `start`, `end`, `note`
- `DELETE /api/breaks/:id` — снова открыть ранее закрытый промежуток
- `409 Conflict` — выбранный час уже занят

Пример тестового запроса:

```json
{
  "name": "Тестовый клиент",
  "phone": "+70000000000",
  "service": "color",
  "date": "2026-11-16",
  "time": "12:00"
}
```

Время выбирается вручную с точностью до минуты: например, 12:07, 13:25 или 17:30. Бронирование разрешено по будням в пределах рабочего дня **12:00–20:00 (Москва)**, если процедура помещается в график, нет вручную закрытого времени и соблюдён перерыв **3 часа после окончания предыдущей записи**. На сервере проверяются пересечения, а запись выполняется в транзакции с блокировкой даты, чтобы два одновременных запроса не смогли занять пересекающееся время.

## Запуск на ONREZA

1. Импортируйте этот GitHub-репозиторий в ONREZA как Node.js/Compute-проект.
2. Корневая директория `/`; команда запуска `npm start` (установку зависимостей делает система сборки).
3. Подключите существующую PostgreSQL `app_database` к проекту или задайте защищённую переменную окружения `DATABASE_URL` из параметров подключения базы. **Пароли не публиковать на GitHub**.
4. По возможности задайте `CLIENT_ORIGIN` — точный адрес сайта, открывающего API (например, `http://127.0.0.1:5500`). Если сайт опубликован, укажите его HTTPS-origin.
5. Для просмотра записей добавьте **секретную переменную** `ADMIN_TOKEN` в настройках окружения проекта ONREZA. Значение — случайный длинный ключ минимум 24 символа; не сохраняйте его на GitHub, не показывайте на скриншотах. После обновления деплоя откройте `https://АДРЕС-API/admin`, вставьте ключ и нажмите «Показать записи».
6. После деплоя откройте `https://ВАШ-ДОМЕН/api/health` — должна вернуться JSON-строка со статусом ok.
7. В сайте VERONIKA замените `script.js` содержимым `integration/script.js` (адрес API уже задан). В `index.html` найдите старый блок `<select id="time">...</select>` и замените его на `<input type="time" id="time" name="time" min="12:00" max="19:00" step="60" required>`. `script.js` также автоматически заменяет старый `select`, если HTML ещё не обновлён.
8. Для проверки используйте только вымышленные имена/телефоны и два браузера: после первого бронирования второй клиент уже не должен видеть занятое окно.

Сервер создаёт таблицу `bookings` сам при первом старте, если её нет; `schema.sql` также можно выполнить вручную. Пользователь уже создал таблицу в ONREZA — повторное выполнение не требуется.


## Редактирование записей в журнале

После авторизации через `ADMIN_TOKEN` на странице `/admin` возле каждой строки есть две кнопки:

- **Перенести** — выбрать новую дату и время, отправить защищённый `PATCH /api/bookings/:id`. Сервер проверяет будний день, часы работы, длительность услуги, обязательный интервал 3 часа, ручные перерывы и другие записи. Изменения сохраняются в существующей строке PostgreSQL без потери имени, телефона и услуги.
- **Удалить** — после дополнительного подтверждения отправить защищённый `DELETE /api/bookings/:id` и удалить строку из PostgreSQL. Это безвозвратное действие в текущем учебном прототипе.

Редактирование и удаление защищены ключом `ADMIN_TOKEN`. Если время занято, API возвращает `409 Conflict`; после успешного действия журнал можно обновить, а другие клиенты увидят актуальное расписание. При переносе даты или времени SMS ставится в очередь, если настроены SMS.ru и планировщик. При удалении записи ожидающие уведомления отменяются.

## Дополнительные перерывы мастера

В административной панели `/admin` после ввода `ADMIN_TOKEN` появилась секция **«Перерывы мастера»**. Там можно указать дату, произвольное начало и конец (например, `15:00`–`16:00`), необязательное примечание, нажать **«Закрыть время»**, просматривать текущие закрытые периоды и нажимать **«Открыть время»** для удаления перерыва. Закрытие периода с `12:00` до `20:00` закрывает весь рабочий день. Перерывы нельзя создать поверх существующей записи клиента.

Перерывы сохраняются в отдельной таблице `manual_breaks`. Сервер создаёт таблицу автоматически при старте; если база была уже создана ранее, повторно пересоздавать `bookings` не требуется. Сервис применяет закрытые периоды при `GET /api/slots`, `GET /api/availability` и `POST /api/bookings`. API требует ключ администратора для изменения перерывов, клиент не может самостоятельно снять ограничение.

Ручные перерывы **не заменяют** автоматический интервал 3 часа между процедурами. Это дополнительное ограничение. Для публичного использования необходимы подтверждение телефона и антиспам-защита.

## Безопасность и ограничения

Это **учебный прототип**, не публичная запись реальных клиентов. Есть простая защищённая административная панель для просмотра записей, однако нет проверки владения телефоном и полноценной защиты от спама, юридической документации по персональным данным и истории удалённых записей. Не используйте реальные контакты до доработки. Прототип не подключён к Queue. Бесплатный хостинг может иметь ограничения.

## Выбор времени и уведомления по SMS

Клиент видит выпадающий список только свободных часов с шагом 15 минут. Доступность берётся с GET /api/slots и повторно проверяется сервером при записи.
Файл integration/script.js нужно скопировать в локальный сайт вместо script.js и заново опубликовать статический сайт. Сам коммит в API-репозиторий не обновит сайт на статическом хостинге. Поле телефона преобразуется в числовое, автоматически удаляя буквы и разделители.

Уведомления через SMS.ru:
- Новая запись более чем за сутки: SMS за 24 часа до времени визита (Московское время).
- Перенос записи в /admin: SMS о новой дате и времени при ближайшем запуске планировщика.
- После переноса напоминание пересоздаётся по новой дате; после удаления ожидающие SMS отменяются.
- Для записей менее чем за 24 часа автоматическое напоминание не создаётся.

### Настройка отправки

1. Создайте аккаунт на https://sms.ru/ и получите API ID. SMS являются платными; может потребоваться утверждённое имя отправителя.
2. В переменные окружения ONREZA API добавьте SMS_RU_API_ID (секретный API ID), REMINDER_CRON_TOKEN (случайный секрет минимум 24 символа, отдельный от ADMIN_TOKEN). Необязательно: SMS_RU_FROM (согласованное у SMS.ru имя отправителя).
3. Перезапустите/повторно разверните API из текущего GitHub main, чтобы создалась таблица booking_notifications.
4. На https://cron-job.org/ создайте задание: URL https://veronika-api-lashkovmaximik-g7tm.onreza.app/api/internal/notifications/run; метод POST; каждая минута; HTTP-заголовок Authorization со значением Bearer ВАШ_REMINDER_CRON_TOKEN. Не размещайте секрет в URL.
5. Проверьте ответ запуска: configured:true и поля sent/failed означают, что обработчик запущен; configured:false — нет API ID; HTTP 401 — ошибка токена.
6. Проверьте перенос тестовой записи в /admin на свой собственный номер. Не проводите пробные отправки на чужие номера.

Нужны защита от ботов/спама, лимиты SMS и подтверждение владения номером для публичного использования. Обновите политику обработки персональных данных: SMS-информирование как цель, номер телефона и сторонний SMS-провайдер. API подтверждает только принятие SMS сервисом, не фактическую доставку оператором.

Без настройки SMS_RU_API_ID и внешнего расписания уведомления НЕ отправляются автоматически.
