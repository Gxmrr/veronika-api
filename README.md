# VERONIKA — Booking API

Собственный учебный API для записи на маникюр (Node.js, Express, PostgreSQL). Не связан с Queue.

## Маршруты

- `GET /api/health` — проверка сервера и базы
- `GET /api/slots?date=2026-11-16&service=color` — доступные окна для всех услуг с шагом 30 минут
- `GET /api/availability?date=2026-11-16&service=color&time=13:07` — проверить любое выбранное время (до минуты)
- `POST /api/bookings` — создание записи (JSON: имя, телефон, основная услуга, дополнительные услуги `addons`, дата, время)
- `GET /api/bookings` — приватный список записей, требует `Authorization: Bearer ADMIN_TOKEN`
- `PATCH /api/bookings/:id` — перенос существующей записи на дату/время (только администратор, JSON `date` и `time`)
- `DELETE /api/bookings/:id` — удаление записи (только администратор, с подтверждением в интерфейсе)
- `GET /admin` — панель мастера для просмотра записей и управления перерывами по секретному ключу
- `GET /api/breaks` — закрытые окна (нужен `Authorization: Bearer ADMIN_TOKEN`)
- `POST /api/breaks` — закрыть свободный промежуток; JSON `date`, `start`, `end`, `note`
- `DELETE /api/breaks/:id` — снова открыть ранее закрытый промежуток
- `409 Conflict` — выбранный час уже занят

Пример тестового запроса:

```json
{
  "name": "Тестовый клиент",
  "phone": "+70000000000",
  "service": "color",
  "date": "2026-11-16",
  "time": "12:00"
}
```

В клиентской форме время предлагается с шагом 30 минут, независимо от набора услуг; длительности выбранных процедур проверяются отдельно. Длительность каждой добавленной процедуры суммируется с основной услугой. Вручную по-прежнему разрешено указать другое время `HH:MM` с точностью до минуты, если сервер подтверждает доступность. Бронирование разрешено по будням в пределах рабочего дня **12:00–20:00 (Москва)**, если процедура помещается в график, нет вручную закрытого времени и соблюдён перерыв **15 минут между записями**. На сервере проверяются пересечения, а запись выполняется в транзакции с блокировкой даты, чтобы два одновременных запроса не смогли занять пересекающееся время.

## Запуск на ONREZA

1. Импортируйте этот GitHub-репозиторий в ONREZA как Node.js/Compute-проект.
2. Корневая директория `/`; команда запуска `npm start` (установку зависимостей делает система сборки).
3. Подключите существующую PostgreSQL `app_database` к проекту или задайте защищённую переменную окружения `DATABASE_URL` из параметров подключения базы. **Пароли не публиковать на GitHub**.
4. По возможности задайте `CLIENT_ORIGIN` — точный адрес сайта, открывающего API (например, `http://127.0.0.1:5500`). Если сайт опубликован, укажите его HTTPS-origin.
5. Для просмотра записей добавьте **секретную переменную** `ADMIN_TOKEN` в настройках окружения проекта ONREZA. Значение — случайный длинный ключ минимум 24 символа; не сохраняйте его на GitHub, не показывайте на скриншотах. После обновления деплоя откройте `https://АДРЕС-API/admin`, вставьте ключ и нажмите «Показать записи».
6. После деплоя откройте `https://ВАШ-ДОМЕН/api/health` — должна вернуться JSON-строка со статусом ok.
7. В локальном сайте VERONIKA замените только `script.js` содержимым `integration/script.js` и заново опубликуйте статику. Скрипт создаёт кнопки свободного времени и позволяет ручной ввод `HH:MM` и добавляет цифровой ввод `#phone`. `index.html` и Яндекс Карту не удаляйте.
8. Для проверки используйте только вымышленные имена/телефоны и два браузера: после первого бронирования второй клиент уже не должен видеть занятое окно.

Сервер создаёт таблицу `bookings` сам при первом старте, если её нет; `schema.sql` также можно выполнить вручную. Пользователь уже создал таблицу в ONREZA — повторное выполнение не требуется.


## Редактирование записей в журнале

После авторизации через `ADMIN_TOKEN` на странице `/admin` возле каждой строки есть две кнопки:

- **Перенести** — выбрать новую дату и время, отправить защищённый `PATCH /api/bookings/:id`. Сервер проверяет будний день, часы работы, длительность услуги, обязательный интервал 15 минут, ручные перерывы и другие записи. Изменения сохраняются в существующей строке PostgreSQL без потери имени, телефона и услуги.
- **Удалить** — после дополнительного подтверждения отправить защищённый `DELETE /api/bookings/:id` и удалить строку из PostgreSQL. Это безвозвратное действие в текущем учебном прототипе.

Редактирование и удаление защищены ключом `ADMIN_TOKEN`. Если время занято, API возвращает `409 Conflict`; после успешного действия журнал можно обновить, а другие клиенты увидят актуальное расписание. При переносе даты или времени уведомление ставится в очередь для выбранного клиентом канала (Telegram или P1SMS) при настроенном планировщике. При удалении записи ожидающие уведомления отменяются.

## Дополнительные перерывы мастера

В административной панели `/admin` после ввода `ADMIN_TOKEN` появилась секция **«Перерывы мастера»**. Там можно указать дату, произвольное начало и конец (например, `15:00`–`16:00`), необязательное примечание, нажать **«Закрыть время»**, просматривать текущие закрытые периоды и нажимать **«Открыть время»** для удаления перерыва. Закрытие периода с `12:00` до `20:00` закрывает весь рабочий день. Перерывы нельзя создать поверх существующей записи клиента.

Перерывы сохраняются в отдельной таблице `manual_breaks`. Сервер создаёт таблицу автоматически при старте; если база была уже создана ранее, повторно пересоздавать `bookings` не требуется. Сервис применяет закрытые периоды при `GET /api/slots`, `GET /api/availability` и `POST /api/bookings`. API требует ключ администратора для изменения перерывов, клиент не может самостоятельно снять ограничение.

Ручные перерывы **не заменяют** автоматический интервал 15 минут между процедурами. Это дополнительное ограничение. Для публичного использования необходимы подтверждение телефона и антиспам-защита.

## Безопасность и ограничения

Это **учебный прототип**, не публичная запись реальных клиентов. Есть простая защищённая административная панель для просмотра записей, однако нет проверки владения телефоном и полноценной защиты от спама, юридической документации по персональным данным и истории удалённых записей. Не используйте реальные контакты до доработки. Прототип не подключён к Queue. Бесплатный хостинг может иметь ограничения.

## Календарь и выбор времени

В `integration/script.js` используется одна штатная иконка календаря (без накладной кнопки); при выборе выходного показывается пояснение, так как график API — понедельник–пятница. Время выбирается непосредственно из свободных вариантов в выпадающем списке при фокусе поля `#time` или в сетке ниже. Варианты приходят с `/api/slots` и учитывают записи, общую длительность основных/дополнительных процедур, 15 минут подготовки и ручные перерывы мастера. Разрешён также ручной ввод `HH:MM`, проверяемый через `/api/availability` и повторно через `POST /api/bookings`.

Важно: чтобы новое оформление было видно на опубликованном Netlify, перенесите обновлённую логику `integration/script.js` в локальный сайт с сохранением других функций и повторно загрузите всю папку. Одного обновления API на ONREZA недостаточно.

## Основная и дополнительные услуги

Клиент выбирает **одну основную услугу**: простой маникюр (`basic`) или маникюр в один тон (`color`, в форме — «Маникюр с гель-лаком»). Маникюр с дизайном больше не доступен для новых записей.
Дополнительно можно нажимать `+`/`−` у ремонта ногтей (`repair`), донаращивания ногтей (`extension`) и наращивания ногтей (`nails`). Количество каждого вида может быть больше 1; искусственного лимита нет, но общее время процедур должно помещаться в рабочий день 12:00–20:00.

В `integration/script.js` интерфейс выбора допов создаётся автоматически после `#service` и стили тоже добавляются через JS, поэтому **не нужно вставлять JavaScript в `style.css`**. Сайт должен иметь `#booking-form` и `#service` и подключать этот скрипт.

Клиент передаёт в запрос `POST /api/bookings` `addons` как объект, например `{"repair":2,"extension":1}`; при выборе часов этот же объект сериализуется в параметр `addons` для `GET /api/slots` и `GET /api/availability`.

Примерные длительности (можно скорректировать под мастера): простой маникюр 60 минут, в один тон 90 минут; каждое дополнение на ОДИН ноготь — ремонт 15 минут, донаращивание 25 минут, наращивание 25 минут. Все процедуры суммируются, а между разными клиентами автоматически учитывается 15 минут для подготовки рабочего места. Время начала предлагается каждые 30 минут, если весь комплекс услуг помещается в график. Исторические записи с самостоятельной услугой наращивания по-прежнему считаются по старому нормативу 120 минут. Ручное время HH:MM тоже проверяется по общему расписанию.

PostgreSQL хранит `bookings.addons` в JSONB. При запуске API недостающий столбец добавляется автоматически, старые записи остаются и получают пустой объект `{}`. В `/admin` мастер видит основные и дополнительные услуги вместе с количеством, а перенос использует общую длительность процедур.

Старые записи на маникюр с дизайном остаются в базе; для расчёта их длительности сохраняется норматив 120 минут. Не требуется заново создавать БД.

После коммита GitHub сервер обновляется через ONREZA, а статический сайт Netlify Drop всё ещё требует вручную обновить локальную логику `script.js` и повторно загрузить папку `index.html`, `script.js`, `style.css`. **Не заменяйте весь JS**, если там есть другая логика меню, карты или анимации.

## Исправление лимитов журнала

Раньше для администратора действовало ограничение 12 запросов за 15 минут. Каждое удаление сопровождалось обновлением списка записей и перерывов, и лимит быстро заканчивался. Теперь запросы с правильным ADMIN_TOKEN не ограничиваются лимитами для гостей, а попытки с неправильным токеном и публичные запросы по-прежнему ограничиваются.

В /admin у каждой записи есть кнопка «Написать». После удаления или переноса появляется блок с готовым текстом уведомления, WhatsApp-ссылкой по номеру гостя и кнопкой копирования. Это бесплатная РУЧНАЯ связь через WhatsApp, если он установлен у клиента. Сообщение отправляется только самим мастером при подтверждении в приложении. После удаления номер остаётся только во временном блоке до перезагрузки страницы, не в базе.

## Выбор канала напоминаний

В форме VERONIKA есть отдельное поле **«Куда отправить напоминание за час до записи?»**. Клиент самостоятельно выбирает один вариант:

- Без напоминания (`none`) — вариант по умолчанию, никуда не отправляем.
- Telegram (`telegram`) — только если владелец включил Telegram-бота; после отправки формы клиенту нужна персональная ссылка, которую он должен открыть, чтобы запустить бота.
- Обычное SMS (`sms`) — через P1SMS.ru, появляется в списке только если в ONREZA заданы ключ, канал и `P1SMS_SMS_ENABLED=true` после успешной отправки тестового SMS на собственный номер.

Доступность методов для формы: `GET /api/reminder-options`, ответ `{telegram: boolean, sms: boolean}`. Канал передаётся в POST `/api/bookings` в поле `reminderChannel`, сохраняется в `bookings.reminder_channel` и используется для напоминаний за час по Москве. **Без явного выбора нет отправки.** SMS не используется как автоматическая замена Telegram, и Telegram не используется как замена SMS. Старые явные подключения Telegram сохраняются миграцией; у всех остальных старых записей значение по умолчанию `none`.

При переносе повторно планируется напоминание за час до новой даты. Для выбранного Telegram уведомление о переносе отправляется в чат при следующем запуске планировщика, если бот запущен и настроен. После удаления записи ожидающие уведомления удаляются вместе с ней. В журнале доступна отдельная кнопка для ручного сообщения клиенту через WhatsApp.

### Подключение Telegram

1. В Telegram создайте своего бота через `@BotFather`.
2. В секретных переменных ONREZA задайте `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` (без @), `TELEGRAM_WEBHOOK_SECRET` (случайная строка 20–128 символов из латинских букв/цифр/`_`/`-`) и `TELEGRAM_PUBLIC_URL` (публичный HTTPS-адрес API, например `https://veronika-api-lashkovmaximik-g7tm.onreza.app`).
3. После деплоя API автоматически регистрирует Telegram webhook. В форме будет доступен Telegram. После оформления записи клиент выбирает персональную ссылку и запускает бота, чтобы включить напоминание. Команда `/stop` отключает канал, не удаляя саму запись.
4. Для своевременного запуска очереди установите `REMINDER_CRON_TOKEN` (секрет минимум 24 символа) и на cron-job.org создайте POST-запрос каждую минуту на `https://veronika-api-lashkovmaximik-g7tm.onreza.app/api/internal/notifications/run` с заголовком `Authorization: Bearer ВАШ_REMINDER_CRON_TOKEN`. Не передавайте секрет в URL и не публикуйте его.

### Подключение P1SMS.ru (пробный баланс)

P1SMS.ru использует отдельный API (не путать с ip1sms.com). Источник структуры запроса: опубликованный пример интеграции [p1sms_free.pl](https://github.com/AlexandreFrolov/shop2you_zabbix_monitoring/blob/main/p1sms_free.pl), в нём используются POST https://admin.p1sms.ru/apiSms/create и JSON с полями apiKey, phone, sms[].phone, sms[].channel, sms[].text и при необходимости sms[].sender. Окончательно актуальность контракта и тариф отправителя нужно проверить в кабинете P1SMS → API до отправки клиентам.

1. Войдите в https://admin.p1sms.ru/ → «Другое»/«Профиль» → блок «API» или «Инструкция по API». Получите API-ключ и узнайте разрешённый канал: `digit` или `char`. Не присылайте ключ в чат и не коммитьте в GitHub.
2. В проекте ONREZA → переменные окружения задайте:
    - `P1SMS_API_KEY` — личный API-ключ
    - `P1SMS_CHANNEL` — `digit` или `char`, по вашему тарифу в P1SMS
    - `P1SMS_TEST_PHONE` — собственный телефон, формат 79XXXXXXXXX
    - `P1SMS_SMS_ENABLED=false` — обязательно на этапе теста
    - `P1SMS_DAILY_LIMIT=2` — ограничение автосообщений в день после включения (для пробного баланса рекомендуем 1–2)
    - `P1SMS_SENDER` — только если этот sender зарегистрирован и разрешён в кабинете, например для канала `char`.
3. Дождитесь деплоя API с GitHub и откройте `https://veronika-api-lashkovmaximik-g7tm.onreza.app/admin`. Введите `ADMIN_TOKEN` и нажмите **«Проверить SMS»**. Подтвердите отправку: тест идёт **только на P1SMS_TEST_PHONE**, не более одного раза за московские сутки, даже если P1SMS не дал однозначного ответа. Проверяйте телефон и историю/стоимость в P1SMS перед повтором; отправка расходует баланс.
4. При получении тестового SMS проверьте стоимость и корректность номера отправителя. Только после этого замените `P1SMS_SMS_ENABLED` на `true` и повторно разверните ONREZA. Тогда `GET /api/reminder-options` вернёт `sms:true`.
5. Опубликуйте обновлённый сайт VERONIKA в Netlify, скопировав логику из `integration/script.js` в локальный `script.js`, не удаляя другие функции. После этого клиенты смогут самостоятельно выбрать **SMS** в поле напоминания. Сообщение будет запланировано за 1 час до визита по Москве; при переносе создаётся ещё одно сообщение с новой датой, если SMS-канал включён.
6. Чтобы автоматическая очередь отправляла SMS вовремя, нужен планировщик: `REMINDER_CRON_TOKEN` не короче 24 символов в ONREZA; на cron-job.org настроить POST каждую минуту на `https://veronika-api-lashkovmaximik-g7tm.onreza.app/api/internal/notifications/run`, заголовок `Authorization: Bearer ВАШ_REMINDER_CRON_TOKEN`.

**Безопасность пробного баланса:** автоматическая отправка изначально выключена и требует явной переменной `P1SMS_SMS_ENABLED=true`. Предел `P1SMS_DAILY_LIMIT` по умолчанию 2 автоматические попытки в сутки, учитываются попытки, даже если провайдер ответил неоднозначно. При неясной ошибке **нет автоматических повторов платного SMS**, чтобы предотвратить двойные списания; соответствующее уведомление попадёт в статус `failed`. Настройка по умолчанию экономит баланс, но после достижения лимита оставшиеся клиенты **не получат** SMS — увеличивать лимит следует только после проверки тарифов, реальной стоимости и баланса.

**Важно:** успех HTTP-запроса в P1SMS означает лишь принятие запроса на обработку, а не подтверждение доставки. Не обещайте доставку до проверки истории P1SMS и реального SMS на собственном телефоне. Обычные SMS платные, 40 ₽ — пробный баланс, а не бесплатная постоянная рассылка. Для SMS и Telegram учитывайте согласие клиента, цель обработки номера и условия P1SMS.

### Обновление проекта

1. После коммитов дождитесь нового успешного деплоя API в ONREZA; при старте будут добавлены новые поля PostgreSQL.
2. В своём локальном сайте обновите только логику записи из GitHub `integration/script.js`, не удаляя JS меню, анимаций, карты или модального окна конфиденциальности.
3. Сохраните файлы и заново загрузите **всю папку** (`index.html`, `script.js`, `style.css`) в существующий проект Netlify. GitHub-коммиты в API-репозитории **не меняют** статическую страницу сами по себе.
4. Проверьте `GET /api/reminder-options`; при отсутствии настройки ожидается `telegram:false`, `sms:false`. После настройки бота появится `telegram:true`. Канал SMS остаётся `false`, пока P1SMS не настроен и не включён после теста.

Текущая техническая реализация проверена на уровне синтаксиса. Реальная работоспособность ONREZA, Telegram, cron и SMS зависит от ваших настроек и должна проверяться отдельно.
