# VERONIKA — Booking API

Собственный учебный API для записи на маникюр (Node.js, Express, PostgreSQL). Не связан с Queue.

## Маршруты

- `GET /api/health` — проверка сервера и базы
- `GET /api/slots?date=2026-11-16&service=color` — подсказки свободных часов с шагом 15 минут
- `GET /api/availability?date=2026-11-16&service=color&time=13:07` — проверить любое выбранное время (до минуты)
- `POST /api/bookings` — создание записи (JSON: имя, телефон, услуга, дата, время)
- `GET /api/bookings` — приватный список записей, требует `Authorization: Bearer ADMIN_TOKEN`
- `GET /admin` — панель мастера для просмотра записей с защитой по ключу
- `409 Conflict` — выбранный час уже занят

Пример тестового запроса:

```json
{
  "name": "Тестовый клиент",
  "phone": "+70000000000",
  "service": "color",
  "date": "2026-11-16",
  "time": "12:00"
}
```

Время выбирается вручную с точностью до минуты: например, 12:07, 13:25 или 17:30. Бронирование разрешено по будням в пределах рабочего дня **12:00–20:00 (Москва)**, если процедура помещается в график и соблюдён перерыв **3 часа после окончания предыдущей записи**. На сервере проверяются пересечения, а запись выполняется в транзакции с блокировкой даты, чтобы два одновременных запроса не смогли занять пересекающееся время.

## Запуск на ONREZA

1. Импортируйте этот GitHub-репозиторий в ONREZA как Node.js/Compute-проект.
2. Корневая директория `/`; команда запуска `npm start` (установку зависимостей делает система сборки).
3. Подключите существующую PostgreSQL `app_database` к проекту или задайте защищённую переменную окружения `DATABASE_URL` из параметров подключения базы. **Пароли не публиковать на GitHub**.
4. По возможности задайте `CLIENT_ORIGIN` — точный адрес сайта, открывающего API (например, `http://127.0.0.1:5500`). Если сайт опубликован, укажите его HTTPS-origin.
5. Для просмотра записей добавьте **секретную переменную** `ADMIN_TOKEN` в настройках окружения проекта ONREZA. Значение — случайный длинный ключ минимум 24 символа; не сохраняйте его на GitHub, не показывайте на скриншотах. После обновления деплоя откройте `https://АДРЕС-API/admin`, вставьте ключ и нажмите «Показать записи».
6. После деплоя откройте `https://ВАШ-ДОМЕН/api/health` — должна вернуться JSON-строка со статусом ok.
7. В сайте VERONIKA замените `script.js` содержимым `integration/script.js` (адрес API уже задан). В `index.html` найдите старый блок `<select id="time">...</select>` и замените его на `<input type="time" id="time" name="time" min="12:00" max="19:00" step="60" required>`. `script.js` также автоматически заменяет старый `select`, если HTML ещё не обновлён.
8. Для проверки используйте только вымышленные имена/телефоны и два браузера: после первого бронирования второй клиент уже не должен видеть занятое окно.

Сервер создаёт таблицу `bookings` сам при первом старте, если её нет; `schema.sql` также можно выполнить вручную. Пользователь уже создал таблицу в ONREZA — повторное выполнение не требуется.

## Безопасность и ограничения

Это **учебный прототип**, не публичная запись реальных клиентов. Есть простая защищённая административная панель для просмотра записей, однако нет SMS-подтверждения, удаления/изменения записей, полноценной защиты от спама, юридической документации по персональным данным. Не используйте реальные контакты до доработки. Прототип не подключён к Queue. Бесплатный хостинг может иметь ограничения.
